# Design authority matrix

Conflict order:

1. Explicit user brief
2. Product truth and unchanged functional requirements
3. Accessibility, usability, reduced motion, and readable contrast
4. Platform conventions
5. Established design system
6. Selected mode: Persuade, Operate, Read, or Experience
7. Visual-expression rules

| Decision | Authority |
|---|---|
| Product context, IA, task flow, responsive structure | Impeccable |
| Accessibility, error states, i18n, performance, hardening | Impeccable |
| Layout character, typography expression, density, motion | Taste, within the hierarchy |
| Existing design-system consistency | Impeccable |
| Anti-generic composition and visual-slop review | Taste |
| Implementation quality | Both |
| Final defect report | One consolidated report; highest severity wins |

Taste modules never authorize fabricated tool execution, arbitrary dependency changes, inaccessible motion/contrast, or loss of existing functionality.
